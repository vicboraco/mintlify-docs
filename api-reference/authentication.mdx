Every request you make to the Piixan AI API must be authenticated with an API key. You pass your key as a Bearer token in the `Authorization` header of each HTTP request — there are no session cookies or alternative auth schemes for API access. Keys are tied to your account and inherit the scope you assign at creation time.

## Creating API Keys

Generate your API keys from the [API Keys settings page](https://app.piixan.ai/settings/api-keys) in your Piixan AI dashboard. You can create multiple keys with different scopes to isolate access for different applications or environments.

<Steps>
  <Step title="Open the API Keys page">
    Navigate to [https://app.piixan.ai/settings/api-keys](https://app.piixan.ai/settings/api-keys) in your dashboard.
  </Step>
  <Step title="Create a new key">
    Click **Create New Key** and choose the appropriate scope for your use case (see [API Key Scopes](#api-key-scopes) below).
  </Step>
  <Step title="Name your key">
    Enter a descriptive name — for example, `production-backend` or `ci-pipeline` — so you can identify the key later.
  </Step>
  <Step title="Copy the key immediately">
    The full key value is shown **only once** at creation time. Copy it now and store it securely. If you lose it, you must revoke the key and create a new one.
  </Step>
</Steps>

## Passing the API Key

Include your API key in the `Authorization` header of every request using the `Bearer` scheme. The examples below show the same authenticated POST request in curl, Python, and JavaScript.

<CodeGroup>

```bash curl
curl --request POST \
  --url https://api.piixan.ai/v1/completions \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "prompt": "Summarize the following text:",
    "input": "Piixan AI is an intelligent platform..."
  }'
```

```python Python
import requests

url = "https://api.piixan.ai/v1/completions"
headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json",
}
payload = {
    "prompt": "Summarize the following text:",
    "input": "Piixan AI is an intelligent platform...",
}

response = requests.post(url, headers=headers, json=payload)
print(response.json())
```

```javascript JavaScript
const response = await fetch("https://api.piixan.ai/v1/completions", {
  method: "POST",
  headers: {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    prompt: "Summarize the following text:",
    input: "Piixan AI is an intelligent platform...",
  }),
});

const data = await response.json();
console.log(data);
```

</CodeGroup>

## API Key Scopes

When you create a key, you assign it one of three scopes. Choose the narrowest scope that satisfies your application's needs — this limits the blast radius if a key is ever compromised.

| Scope   | Permissions                                        |
|---------|----------------------------------------------------|
| `read`  | GET requests only                                  |
| `write` | GET and POST requests                              |
| `admin` | Full access including webhook management           |

## Error Responses

Authentication errors return one of two status codes depending on the nature of the failure.

**401 Unauthorized** — the key is missing, malformed, or has been revoked:

```json
{
  "error": {
    "code": "invalid_api_key",
    "message": "The provided API key is invalid or has been revoked."
  }
}
```

**403 Forbidden** — the key is valid but does not have the scope required for the requested operation:

```json
{
  "error": {
    "code": "insufficient_permissions",
    "message": "Your API key does not have permission to perform this action."
  }
}
```

<Warning>
  Never commit API keys directly to source control. Store them as environment variables (e.g., `PIIXAN_API_KEY`) and load them at runtime. Use a secrets manager such as AWS Secrets Manager, HashiCorp Vault, or your CI/CD platform's built-in secrets store for production deployments.
</Warning>
